Reflection 公布 Beam：5010 亿参数的开放权重模型，权重本月稍后才发布

Reflection 博客页眉写 October 5, 2026。公司介绍 Beam，称这是它的第一款开放权重模型：稀疏混合专家，总参数 5010 亿，每个 token 激活 230 亿，面向编程、推理和智能体。预训练使用 23.8 万亿 token。强化学习在 1.05 万张 NVIDIA GB300 上训练 4 周，产生超过 1 亿次 rollout，单次上下文最长 256K token；训练和评分大约用了 13 亿个沙箱，并准备了约 100 万个编程、智能体和理工环境。

页面写，Beam 仍在做最后的红队测试和评估，现在可以登记早期访问。权重、技术报告、模型卡和开发者工具计划在本月稍后发布；权重许可证写的是 Apache 2.0，并会带上运行、评估和微调所需的文档与工具。博客称已经在训练下一款模型。

公司称，Beam 在编程和智能体任务上可以和更大的 GLM 5.2 竞争，并接近 Qwen 3.8-Max；原始能力上 Kimi K3 仍然在前面，Beam 的卖点是推理时更省计算。它写，在高级推理基准上分数与 GLM-5.2 相当，推理计算大约少 3 到 4 倍。这个倍数是估算：生成前向计算约为 2 × 每 token 激活参数 × 平均生成 token，每个乘加计两次，不含提示 prefill、与上下文有关的注意力和部署开销。对照用的他人分数来自 Artificial Analysis 和 DataCurve。

博客表格里，Beam 的 DeepSWE v1.1 是 44.4，GLM 5.2 是 44.0，GLM 5.3 是 61.0，Kimi K3 是 68.0。Terminal Bench v2.1 是 80.1，GLM 5.2 是 81.0。不用工具的 HLE 是 36.2，GLM 5.2 是 40.5，Kimi K3 是 46.9。表里的 NR 表示对方没有公布该分数。预训练写明在 6144 张 GB300 NVL72 上不到 4 周完成，后期 goodput 为 92.3%。中训练把有效上下文扩到 100 万 token。安全评测数字留到以后的技术报告，这篇没有给。

  • 分数和 3 到 4 倍效率是公司自己的表和估算，不是独立复测。未调用早期访问。

OpenAI 说明欧盟文本水印：ChatGPT 和 Codex 先在欧盟，API 今天起全球可选

OpenAI 新闻源的时间是 2026-10-05T15:00:00+00:00。公告写，为回应欧盟人工智能法案对生成文本要能被机器识别的要求，公司说明文本水印做法。技术名叫 textGrain：在模型选词里加入看不见的统计信号，检测器据此判断一段文字是否带有 OpenAI 水印。技术报告会在未来数周补充细节，并计划把技术开源。

从今天起，全球的 API 客户可以为选定模型选择打开文本水印，默认关闭。未来数周，欧盟境内符合条件的 ChatGPT 和 Codex 用户、所有套餐，会给文本输出加上这种看不见的水印。公司写明，发布时不把文本水印做成全球默认。

检测器从今天起接受申请，最初只给获批的研究人员和专业机构，按个案授予，用来评估和改进文本来源标注。工具只报告是否检测到 OpenAI 水印，不识别用户，也不显示提示或对话。不向公众开放。

在目标误报率 1% 时，检测器在大约 80% 的 200 token 段落和大约 95% 的 400 token 段落里识别出水印，材料例如心理学；数学这类选词余地更小的内容，检出率明显更低。把 400 token 段落里 10% 的词换成同义词，检出率从大约 92% 降到 66%；换成 25% 则降到 17%。公司写，没有检测到水印不能证明是人写的。在 Astra（max）的一组基准上，加水印和不加水印没有看到有意义的表现差异：Artificial Analysis Intelligence Index 从 49.57 分到 49.76 分，DeepSWE v1.1 从 72.80% 到 71.68%。

  • 欧盟的 ChatGPT 和 Codex 是未来数周，不是今天已经全量打开。API 是今天可选、默认关闭。
  • 检出率和基准对照是公司自己的评估。未申请检测器，也未实测水印开关。
  • 图像和音频的公开核验工具不在这次文本政策里改动。

GitHub 公开 ReviewBench，用 219 个拉取请求衡量 AI 代码审查

GitHub 博客标明的发布时间是 2026-10-05T15:59:40+00:00。GitHub 发布 ReviewBench，称为 AI 代码审查的离线基准，今天可以在 review-bench.ai 使用。语料是 219 个公开拉取请求，来自 187 个公开、采用开源许可证的仓库，覆盖 19 种语言。语言和仓库规模的分布对照了 1.039 亿个 GitHub 拉取请求；拉取请求的改动规模则偏向可审查的中段和长尾。最大的单个仓库只占 4.6%。

标准答案来自人类审查、作者后续提交、确定性分析工具和多个前沿模型，再按同一标准去重。一条发现只有在真实、相关且非琐碎时才算真阳性。评分模型写的是 Claude Sonnet 5。发布前，没有参与建库的资深工程师独立重标了每条标准答案，与 ReviewBench 的真假阳性判断一致率为 96.6%。

指标分两类。Grounded 的精确率、召回率和 F1 只对照已有标准答案。Augmented 还会把标准答案里没有的发现交给评判者单独判断真假。跨系统比较时，页面以 grounded recall 为主。完整数据集、评分标准、评判提示、评判模型配置和自助运行器公开。提交到排行榜前，分数保持私有，直到维护者审核；只有超过该代理当前榜上分数，或是第一次上榜，才会公开。

页面用一次轻量级实验说明离线信号和生产实验同向：多模型集成审查相对生产环境的单审查对照，线上 A/B 的处理率上升 8.0%，召回上升 13.6%，评论量上升 61%，每次审查成本下降 8.0%。严重级别上，ReviewBench 预测关键评论增加 227%，线上是 262%。

适用范围：
  • 这是研究预览。未在 review-bench.ai 上跑过代理，也未核对 219 个拉取请求的清单。
  • 96.6% 和线上百分比是 GitHub 这篇博客给出的数字。
  • Copilot 代码审查本身没有在这篇里改版。实验数字是他们用这个基准观察自己产品的例子。
