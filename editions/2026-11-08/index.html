llama.cpp 让没进缓存的 MoE 专家改在 CPU 上算

llama.cpp 把 PR 30966 合进 master。没进缓存的 MoE 专家可以按 --moe-cache-cpu-share 放到 CPU 上算，并带了一个调参脚本。作者在自己的机器上，share 为 0.95 时写到每秒 47.6 个 token。

限定：47.6 是作者单机日志，本期没有复跑。

原文 · GitHub
详细与核验

GitHub API 显示 ggml-org/llama.cpp 的 PR 30966 由 am17an 提交，2026-10-22T08:12:09Z 打开，2026-11-07T16:20:59Z 合入 master。merge commit 是 e95426f16982054c379ca7bdc8186996dd22f0fe。变更是 1169 行新增、183 行删除、18 个文件、14 个提交。

合入说明写，未命中缓存的专家会按 --moe-cache-cpu-share 在 CPU 上执行。--moe-cache-mib 和 --moe-cache-cpu-share 是两个参数。scripts/moe-cache-tune.py 会多次跑 llama-server，用来选一组参数。

PR 正文附了一台桌面电脑、模型 Qwen3.8-Flash-Next IQ4_NL 的记录。缓存 6464 MiB 时，share 0 是每秒 24.2 token，share 0.95 是每秒 47.6 token。这些是作者日志，不是 llama.cpp 发布的基准。作者建议的配置是 --moe-cache-mib 24000 --moe-cache-cpu-share 0，对应的每秒 83.0 token 是预测输出，不是这次实测。
